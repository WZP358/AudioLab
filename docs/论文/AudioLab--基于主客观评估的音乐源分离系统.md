## 一、系统概述

​	在自研MSS算法模型的过程中遇到了三个痛点：其一，实验数据分散存储、缺乏统一管理；其二，主客观评估割裂、难以全面衡量算法性能；其三，数据可视化难，结果对比不方便。

​	基于此，现推出AudioLab系统作为实验辅助平台，以软件工程方法解决这三个问题（如图1所示）。

​	AudioLab 是面向音乐源分离（Music Source Separation, MSS）模型的综合评测平台，目标是将“数据准备、分离执行、结果分析、主客观评估、统计反馈”整合为统一工作流，成为协调训练者与音频专家工作的枢纽（如图2所示），以缩短模型训练周期、提升模型质量。系统以标准化资源单元（Mixture + Gold Vocals/Drums/Bass/Other）为基础，支持在同一数据语境下对不同算法进行可复现实验比较，降低评测标准不一致带来的结论偏差。

​	平台当前面向两类核心角色：专家用户与管理员。专家侧负责任务创建、结果试听、主观评分（客观评分自动生成）与对比分析；管理员侧负责账号审批、资源治理、系统配置、通知与日志审计。算法层已集成 MDX23C、Demucs4HT、Band Split RoFormer、SCNet，并预留自研模型接口，具备持续扩展能力。

## 二、总体结构设计

​	系统采用分层解耦架构，分为数据层、技术层、业务层、服务层（如图3所示）。
（1）服务层：统一门户、任务交互、结果播放、评测分析、公共资源、消息通知与管理控制等用户可见能力。
（2）业务层：JWT+RBAC 认证授权、用户审批、任务与队列调度、Stem 文件管理、主客观评测、资源库管理、配置与统计分析等核心业务逻辑。
（3）技术层：React 前端 + FastAPI 后端，配套异步任务队列管理器、MSS 分离引擎、音频分析与指标计算组件。
（4）数据层：MySQL 持久化保存数据（用户、任务、评分、资源、通知、配置、日志等），文件系统存储上传音频与分离结果。

![图3 总体架构图](../图片/总体架构图.png)

​	该架构通过“前后端分离 + 任务异步化 + 模型引擎抽象”实现职责边界清晰、部署弹性较好、功能可持续演进的系统目标。

## 四、总体功能设计

​	本平台面向音乐源分离算法的实验评测与应用验证，围绕“资源管理—任务提交—分离计算—结果分析—主观评价—反馈迭代”的闭环开展总体功能设计。平台以统一的任务编排与可追溯的数据记录为核心，将算法能力封装为可配置、可复现、可对比的服务形态，从而支撑多模型、多数据与多轮评测条件下的规范化实验流程。

​	如图5所示，平台的业务流程由“专家评测场景”和“管理员运营场景”共同构成：专家侧完成注册/登录与资质申请后，可在资源中心选择或上传音频资源，并在参数配置界面完成模型与关键超参数设定，随后提交分离任务并在任务列表中进行队列管理与进度跟踪；任务完成后，系统提供结果试听与可视化分析入口，支持对混合音频与分离音轨进行对照审听，并在统一的评分入口提交主观评价与改进意见。管理员侧负责专家资质审核、用户与权限管理、系统配置与日志分析，以及通知与反馈的闭环维护，从平台治理层面保障评测过程的可信性与可持续运营。

​	功能模块层面，平台按照“账户与权限、资源中心、分离任务服务、结果呈现与分析、主观评价与统计、运维与审计”进行划分，并以迭代式交付组织研发优先级（图5给出了从核心流程到扩展需求的演进路径）。其中，资源中心提供数据浏览、上传与下载，并与任务系统联动以形成可复现的输入集合；任务服务采用异步执行机制，面向不同算法模型提供一致的调用接口与运行状态管理；结果模块面向评测需求组织展示形态，通过波形/谱图与多轨试听降低对比成本；评价模块沉淀专家评分与文本反馈，并可进一步形成统计指标以支持横向对比与社区化分析。

​	在算法服务流程方面，如图6所示，平台将音乐源分离抽象为标准化流水线：混合音频读入后进行预处理（如重采样、声道规整），再执行 STFT 获得时频表示；随后进入模型选择与推理阶段，支持在多种分离模型之间切换，并输出统一语义的估计结果（如时频掩码或幅度估计）；最后通过逆 STFT 与后处理（如归一化、限幅）生成可直接使用的分离音频。该设计将“模型差异”收敛到推理模块内部，同时保持前后处理与输入输出规范的一致性，便于开展公平对比实验；同时，平台对每次任务的模型版本、参数配置与数据来源进行固化记录，为实验可复现性、结果可追溯性与后续统计分析提供基础支撑。

​	总体而言，平台层面的功能创新主要体现在：以用户故事地图驱动的端到端评测闭环（图5）、以统一接口封装多模型源分离流水线并暴露可控参数（图6）、以及面向对比评测的结果可视化与主观评价机制的协同设计，从而在“算法研究—工程实现—评测验证”之间建立可持续、可扩展的连接。
